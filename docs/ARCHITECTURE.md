# Architecture

Current accepted contracts, organized by subsystem. For unfinished requirements and measured evidence see [STATUS](STATUS.md); for setup see [DEVELOPMENT](DEVELOPMENT.md). Versions live in Cargo.toml/Cargo.lock and rust-toolchain.toml. Edit the relevant section when a contract changes; do not prepend checkpoint reports.

## Platform and ownership

Windows 10 22H2+ x64, Rust/MSVC. winit owns events; egui renders through the patched egui-directx11 adapter, not eframe/wgpu. FFmpeg supplies media codecs, image/png supply image decoding, and D3D11/DXGI supply presentation.

| Boundary | Owns | Must not expose |
|---|---|---|
| towavue-core | Time, commands, history, geometry, tab and folder contracts | Unsafe code, Windows/FFmpeg types |
| towavue-runtime-windows | Native windows, COM/FFI, FFmpeg, D3D11, WASAPI, Shell, workers/queues/clocks | Native frame/COM/FFmpeg pointers to app or core |
| towavue-app | Event loop, UI state, tab orchestration, command dispatch | Ownership of native decode/render handles |

Unsafe operations stay behind safe runtime interfaces with explicit lifetime, thread, and synchronization invariants. Runtime frame leases own native surfaces; app receives safe metadata/events or RGBA images.

Keep the single-D3D11-device design: hardware decode, video processing, image/UI rendering, and all host windows use the same adapter/device. D3D11VA falls back to software, not CUDA/QSV. Default audio is event-driven WASAPI Shared, not Exclusive.

## Playback, timing, and recovery

- Video and audio use independent demux/decode feeds and bounded queues. Audio output waits must not block video initialization or paused Seek. Do not drop packets or normal audio samples to relieve backpressure.
- Use the selected FFmpeg best streams consistently for playback, preview, waveform, and export. AVIF image display/preview and sequence export explicitly select timed color/auxiliary-alpha tracks: primary still items may have the same IDs and are not animation sources. Static AVIF display selects the primary item and its associated alpha property/reference.
- Media time is integer nanoseconds relative to the input origin. Audio clock is master while audio runs; monotonic anchors handle priming, video-only playback, and drained audio. Drop only eligible late decoded video frames at presentation; retain terminal video during a longer audio tail.
- Seek invalidates generation, clears queues, seeks/flushes, decodes preroll, and primes at the target. Check the selected key packet's PTS and back up a GOP if necessary; TS retains its packet/byte-position path. Do not replace exact frame selection with approximate keyframe display.
- Audio-only workers reconstruct coarse-timestamp scalar-PCM seek anchors by counting actual prefix packet samples without decoding them, then decoding/clipping at the target. Reuse sequential timestamp/gap rules; do not infer constant packet sizes. Packet side data falls back to decoding the remaining prefix because it can change sample counts. This still reads the prefix; sample-precision formats and compressed-audio seeks retain their existing paths. Decoder/resampler creation stays on the audio worker.
- Frame stepping finds distinct actual PTS before/after the displayed frame through a cancellable software probe, not nominal FPS arithmetic. App queues at most 32 directions and rejects stale tab/session/generation/request results.
- Results are scoped to owner and generation. Cancellation is cooperative at I/O/decode/conversion boundaries, not a promise to interrupt arbitrary FFmpeg or OS calls immediately.
- Volume and rate apply to playback and export. Rate changes preserve pitch but may re-prime; they are not guaranteed gapless.
- Device removal pauses affected sessions and rebuilds all host surfaces on one new device before restoration. Failed recovery retains edits and stopped positions; Retry must not command dead workers. Endpoint recovery preserves the same ownership discipline.
- Fatal playback errors pause the affected active or retained clock and best-effort pause its output without replacing the original error. Late first-frame or audio-drain events must not start a clock unless playback is Playing. Successful graphics restoration does not clear an existing playback failure or turn it into a resumable pause, including at a playback-range boundary.
- HDR/10-bit presentation must follow an explicit validated color path; do not treat unverified passthrough or ignored metadata as HDR support.

## Windows, tabs, and input

- The host shares graphics across windows. Normal launches from the same SID/session/executable forward path-only requests with acknowledgment; failure must not silently create a duplicate host. No live-state transfer between independent old processes.
- Tabs own history, export target/options, image/view/reading state, transport, focus role, and scroll positions. Background audio continues. Hidden video limits decode work and retains a frame without pinning an entire decoder surface pool.
- Moving a tab transfers its live state and shared image data only after the destination is ready; failure leaves the source intact. Filmstrip tear-off opens the original file independently, without copying edits. Hit testing respects actual window occlusion.
- Native DWM caption controls coexist with an input-transparent child render surface. Preserve native hit testing, resizing, system controls, DPI-aware client geometry, monitor work-area placement, grab offsets, and fullscreen restoration.
- Menu, palette, grid, keyboard, pointer, and UIA dispatch shared commands/context rules. Text/IME and explicit custom bindings take precedence over implicit aliases. Do not bypass modal or editing-context guards.
- Menus follow input modality across the menu tree: pointer opening/movement releases fixed keyboard highlights; arrows or UIA enter keyboard navigation. The first Down after pointer use selects the first enabled item. Direct logo menus render the same command content as nested menus and remeasure on opening rather than inherit another section's dimensions.
- Gestures have one owner and commit once on release; Escape, focus loss, stale identity, or incompatible state cancels and restores pre-drag state. Preserve event-time pointer/modifier order, including multiple events in one frame.
- Tab reordering keeps tab geometry fixed until release, with an insertion line instead of a floating-tab projection. Edge scrolling moves the whole strip without changing order. The fixed-thin floating scrollbar owns its presses independently of tab dragging; ordinary and Shift wheel scroll the strip.
- The window host owns native Move/NoDrop cursor feedback during tab drags, including outside the source client. Reorder, merge and detach share Move; invalid destinations use NoDrop. Restore the last normal UI cursor on release/cancellation, and invalidate drag ownership immediately on native cancellation events. No OLE drag loop, custom cursor bitmap or helper window is required.
- Non-active wheel input is processed only when the OS delivers it and the local hit/context permits it; it must not steal focus. Selection and right-drag editing still require focus.
- Native file dialogs and ordinary unsaved confirmations use owned STA work. Unsaved confirmation defaults to Cancel. Stateful export progress, long errors, and editing forms stay in egui.
- Heavy work, metadata/stat calls, Shell calls, dialogs, and export must not block the UI thread. Redraw on input, results, animation, or explicit deadlines, not unconditional idle polling.

## Images, reading, and previews

- Decode static images and animations to safe RGBA frames with delays. Image-crate decoders apply EXIF orientation; AVIF applies quarter-turn/reflection display matrices after merging paired FFmpeg color/gray output. Animated PNG uses the runtime compositor.
- Static PNG foreground/prefetch converts decoded rows directly into the retained RGBA8 canvas, then applies EXIF orientation. Preserve palette/low-bit expansion, rounded 16-to-8-bit conversion, caller/512 MiB canvas limits, cooperative row/read cancellation and tail validation. Non-interlaced PNG avoids a full raw color buffer; Adam7 still needs one bounded raw buffer. Codec/metadata/orientation allocations are additional working memory, not a whole-process cap. APNG retains its separate compositor.
- FFmpeg-backed image timing uses a positive next-PTS interval, or the decoded source frame duration when no such interval exists (including the last frame and first-frame-only previews). Only unknown timing falls back to 100 ms; viewing retains its 10 ms minimum. Software frame duration is a safe value, not a native-frame reference.
- AVIF shares bounded ISO-BMFF control reading with export. Still alpha uses pitm/iref/iprp associations; sequences use timed track IDs, media time bases/durations and validated auxi links. Independent color/alpha demux cursors avoid buffering an entire unmatched plane sequence. Merge only equal-sized/equal-timed frames, before either preview callback or retained publication. Still image items have no presentation timing: discard synthetic demux timestamps/durations so a single-item plane can pair with a grid; timed tracks retain strict timestamp/duration validation. First-only loading stops after that merged frame; use low-delay decode without forcing one worker. Retained RGBA follows the caller budget, with a 512 MiB individual canvas limit; decoder/scaler buffers and dual demux contexts are additional working memory, not a whole-process cap. Cancellation is checked between native calls and packets, not inside a codec call.
- APNG snapshots the affected region immediately before PREVIOUS blending, publishes the displayed canvas, then restores it. First animation PREVIOUS acts as BACKGROUND. An independent default poster is not an animation frame. OVER uses the image crate's pixel operation.
- APNG expands low-bit/palette colors and strips 16-bit to 8-bit. Retained RGBA has a caller budget; canvas + raw frame + PREVIOUS region have a 512 MiB working limit. Neither is a whole-process memory cap.
- Foreground loading is latest-only. A separate prefetch worker can hand an in-progress decode to foreground rather than decoding twice. Normal prefetch uses up to nine neighbors; reading prefetch covers the next spread within budget.
- Decoded-cache hits borrow shared pixel ownership rather than consume entries. A cancelled request or smaller caller budget must not discard a valid hit needed by a newer request; source-stamp invalidation, bounded eviction and explicit clearing still release cache ownership.
- Shared decoded-image cache is bounded to 10 images/256 MiB; display texture cache to 8/256 MiB. Texture-cache entries hold weak decode identities, so they do not extend original-pixel lifetimes after the decoder cache and live presentations release them. Open tabs may pin additional data. Managed textures retain GPU resources, dimensions and samplers, not CPU pixel shadows. Whole uploads release their source reference after creation; validated partial rectangles use UpdateSubresource on the serialized same-device immediate context. Deferred partial updates fail explicitly. Driver transfer/storage allocations are additional working memory.
- First-frame previews are borrowed during decoding; optional JPEG/BMP fast paths and cached thumbnails reduce initial waiting. Previews preserve original dimensions/orientation and never become edit, copy, or export sources.
- For normal one-image navigation, retain the previous full image until the next is ready and presented; queue at most 256 direction commands. During the handoff, disable editing/export/image or path copy. Direct destinations, failures, and incompatible state cancel queued directions.
- Last-image-tab close clears original-image caches even when audio/video tabs remain. All-window-empty GPU Trim occurs once after an empty presentation and one idle second; suppress/cancel it during new media or other work. Do not recreate/flush the device or trim while any media remains.
- Hidden/minimized native windows neither advance image/reading-page animation textures nor schedule animation-only wakeups. The same applies while resampling or an unresolved image-edit failure prevents display; a failed reading page alone does not freeze other valid pages. Keep decoded frames and absolute deadlines; catch up to elapsed animation time on return without reopening the source. Lack of focus alone does not suspend animation. Audio/video polling and unrelated deadlines are unaffected; this is not full window-occlusion detection.
- Host thumbnail cache: 64 entries/16 MiB RGBA, dimensions up to 240×160; duration-success cache: 64 entries; disk preview cache: 64 MiB. Deduplicate requests and reject stale results. Valid generated pixels remain reusable in memory if optional disk storage fails; memory hits do not retry storage. Persistence can retry after eviction or in a new cache instance. Video previews share bounded 16-frame sheets, with single-frame fallback while preparing.
- Non-interlaced static PNG thumbnails sample decoded rows into the bounded target instead of retaining full-resolution RGBA; orientation and 16-to-8-bit rounding match the existing nearest-resize path. Keep source-size limits, row/read cancellation and tail validation. APNG/interlaced PNG retain the existing fallback. This thumbnail-only path must not add a full decode ahead of foreground image loading; codec buffers remain additional working memory.
- Image zoom is cursor-anchored and reflects raw wheel events immediately; actual size uses physical pixels. Pan only overflowing axes. Selection has corner/edge resize, Shift ratio retention, in-bounds movement, and outside-click cancellation. Clicking inside zooms to the selection; the removed crop-preview mode must not return.
- Reading is display-only: 2–10 joined pages, independent first-spread count, axis and order reversal, non-overlapping navigation. Dirty images cannot enter reading; editing/Undo/Redo is disabled there.
- Clipboard copies edited full-resolution pixels or the selection, the current animation frame, or the current source page in reading. Text focus keeps normal text-copy behavior.

## Editing and export

- Source files remain unchanged. Each tab has ordered non-destructive operations and Undo/Redo. Preview and export share operation geometry, but interpolation/compression can prevent byte identity.
- Dirty comparison uses the saved snapshot, not operation count alone: normalize effective settings, compare exact duration-aware timeline intervals, and compare all image pixels when needed. Crop/flip/quarter-turn comparisons use validated signed-stride views of the original RGBA, with bounded cancellation checks and no rendered copy; other raster edits retain the FFmpeg-rendered path. Reuse materialized display pixels; compare on the existing worker, reject stale evidence, and remain dirty while pending. Image tabs retain only accepted comparison results with their current/saved operation snapshots across activation and window transfer, without another pixel buffer. Cancelled/incomplete comparisons restart; changed snapshots invalidate reuse. Undo/Redo history is retained.
- Raster operations apply in order. Crop uses integer pixels (image 1px, video even pixels); the current H.264 path requires at least 16×16 video. Respect SAR/orientation and validate source geometry before applying stored operations.
- Resize exposes Nearest, Bilinear, Bicubic, and Lanczos. Arbitrary rotation uses 0.1-degree geometry and a bounded containing canvas; image alpha interpolation is premultiplied. Video GPU raster stays on the shared device with bounded intermediates, while export is separately encoded. Do not promise GPU/export byte identity or full HDR fidelity.
- Image materialization, rendered dirty comparison and streamed WebP export reuse one worker-owned FFmpeg spatial-filter graph per operation list and contiguous input-size run. An empty operation list instead copies validated RGBA in cancellable 64 KiB chunks, preserving hidden RGB/alpha and delays without a native graph. Current/saved comparison sides have independent graphs; borrowed orthogonal comparisons create none. Rebuild on size changes, emit one output per input with monotonic internal PTS, and retain original frame delays. Graphs do not survive their job or create a global image cache.
- Single-source EditTimeline uses half-open intervals and exact integer mapping for Delete/Keep, gain, stretch, playback, waveform placement, and export. Empty timelines are Undoable but cannot be exported. Waveform rearrangement is an overview, not exact post-tempo PCM.
- Video visual editing is enabled only while the timeline is visible. Audio timeline remains visible even in fullscreen. Selection playback is temporary, stops at the selected end, and suppresses normal repeat/auto-next.
- The CTI triangle owns Seek dragging; its line does not. Time selection supports endpoint resize, gain dragging, and Alt stretch. Time selection uses white 20% difference fill and two 1px dotted boundaries; image selection retains its separate inversion outline.
- Exports run cancellably into owned staging files. Verify source identity, requested metadata, output validity, and cancellation before publication; failed/cancelled work must preserve an existing target. History and saved baseline change only for the matching successful request.
- Audio-only export, peak normalization, and mono/stereo options are explicit per-source output settings. Metadata uses Keep/Set/Remove; UI reads existing values asynchronously and rejects stale snapshots.
- PNG/APNG retains ten supported text fields; JPEG and WebP retain nine supported XMP fields, including JPEG↔static WebP conversion. Preserve supported language/author structures and existing noncanonical date/track values under Keep, even without explicit metadata options; Set validates typed values. Use the existing bounded XMP parser/writers and validate the source before encoding and staged values before publication. Animated WebP→JPEG is rejected before encoding, including one-frame animations. Raster conversion retains its normal encoding behavior; JPEG cannot retain alpha. Unknown XMP, EXIF/IPTC/COM/ICC synchronization and other cross-format metadata transfer are not implied.
- PNG metadata scanning validates CRC, bounded text (128 chunks / 1 MiB stored or expanded), and animation controls. Supported APNG export retains 1–65536 frames, exact delay fractions and loop count, including separate posters.
- JPEG→JPEG with an empty image-operation list rewrites supported XMP directly from the source, preserving every non-XMP byte (compressed samples, EXIF orientation, ICC/IPTC/COM and other markers). Strict cancellable FFmpeg decode-to-null validation precedes the bounded marker splice; source identity, XMP readback and staged publication guards still apply. Actual edits and cross-format output retain their encoding paths. Unknown/technical XMP is still excluded, and XMP Remove does not scrub copies in other metadata.
- APNG export assembles independently encoded RGBA8 PNGs into full-canvas SOURCE/NONE frames without recompressing their IDAT data. Runtime first streams the optional poster + one animation cycle into a staged PNG sequence, then one FFmpeg process applies the edits. Sharing the display compositor avoids divergent OVER rounding and FFmpeg's partial-first-frame demuxer limitation. Poster IDAT precedes animation fcTL/fdAT and is excluded from frame count.
- APNG assembly checks CRC, IHDR agreement, frame counts and controls before metadata readback/publication. Intermediate disk/encoding cost can exceed delta-compressed input, including posterless animations. Full 16-bit/color retention remains a separate limitation.
- GIF→GIF export preserves 1–65536 frames, exact centisecond delays (including zero), and absent/infinite/finite repeat settings. A bounded indexed-frame scan validates source pixels/LZW, geometry, and controls; FFmpeg alone can silently tolerate damaged GIFs even with `-xerror`. FFmpeg edits one cycle into staged RGBA8 PNG snapshots; runtime encodes one snapshot at a time with local palettes and BACKGROUND disposal, preventing stale colors behind newly transparent pixels. Validate PNG structure/CRC, equal dimensions, frame count, and final GIF controls before publication.
- GIF palette construction keeps exact edited RGBA colors when they fit 256 entries, including transparency. Alpha below 128 becomes transparent; hidden RGB is discarded. Larger palettes use NeuQuant, with opaque pixels prevented from selecting the transparent entry. Intermediate PNG encoding/disk cost, quantization quality, and binary alpha remain limitations; 512 MiB canvas/decoder bounds are not a process-memory cap, and one-frame quantization is not interruptible. GIF metadata editing and arbitrary extension/ICC retention are unsupported.
- Animated GIF→APNG (.png/.apng) reuses GIF validation/edited PNG snapshots and APNG assembly/readback. Retain every frame and exact centisecond delays (numerator/100), including zero. [GIF repetition counts](https://pkg.go.dev/image/gif#GIF) exclude the first play, while [APNG num_plays](https://www.w3.org/TR/png/#acTL-chunk) includes it: absent GIF looping becomes 1, finite N becomes N+1, infinite becomes 0. Encode full-canvas SOURCE/NONE frames, without GIF palette re-quantization or a separate poster. Source identity/cancellation/staging guards remain; unsupported animated destinations fail rather than flatten. Static GIF conversion is unchanged; GIF metadata/unknown extensions are not transferred.
- Animated WebP→WebP saves retain 1–65536 frames, raw 24-bit millisecond delays (including zero), 16-bit loop count, and the ANIM background hint. Runtime shares the display decoder/default compositing and raster edits one frame at a time, then embeds lossless VP8L full-canvas NO_BLEND/NO_DISPOSE snapshots under the [WebP container contract](https://developers.google.com/speed/webp/docs/riff_container#animation). Supported XMP Keep/Set/Remove applies to animations too. Validate outer/nested chunk bounds and padding, bitstream dimensions, decoded frame count/delays, source identity and output controls before publication.
- Animated GIF→WebP reuses GIF validation/edited PNG snapshots and the same lossless WebP snapshot writer. Convert centisecond delays to exact milliseconds and repetition to total plays (absent→1, finite N→N+1, infinite→0). Reject 65536 total plays before encoding because WebP's finite count is limited to 65535; do not truncate or turn it into infinite playback. Use a transparent ANIM background hint, retain interpolated alpha without GIF palette conversion, and verify output controls before publication. GIF metadata/unknown extensions are not transferred.
- Animated WebP→APNG (.png/.apng) streams the same composited/edited RGBA8 frames into PNG snapshots, then uses existing APNG assembly/readback without a second raster edit or separate poster. Preserve 1–65536 frames and total plays directly (0 remains infinite). Reduce each millisecond delay/1000 to lowest terms; reject a numerator exceeding APNG's 16-bit limit before encoding, rather than round timing or split frames. Full-canvas SOURCE/NONE snapshots preserve the app's compositing, not a separate WebP background hint. Cross-format metadata editing/transfer is unsupported; source identity/cancellation/publication guards remain.
- APNG→WebP reuses APNG validation/compositing, the existing FFmpeg edited PNG snapshots and the GIF→WebP lossless snapshot writer. Preserve total plays directly (0 infinite), but reject finite counts above 65535. Convert raw APNG delay fractions (denominator 0 means 100) only when exactly representable as whole milliseconds within WebP's 24-bit limit. Reject separate posters before encoding: WebP has no corresponding independent default image, and silently discarding it or inserting an animation frame is not equivalent. No second compositor, palette conversion or metadata transfer; static PNG conversion remains unchanged.
- WebP→WebP export does not retain the whole decoded sequence or stage a PNG sequence; GIF/APNG→WebP and WebP→APNG incur intermediate PNG cost. Full snapshots/lossless encoding can increase file size and work; long-animation performance remains unmeasured. Canvas RGBA and encoded WebP ANMF payloads are each bounded to 512 MiB and WebP output frames to 16384 per dimension, with the RIFF file limit enforced; these are not a whole-process memory cap. Per-frame codec/filter calls are not interruptible. Other animated WebP conversion destinations are rejected, not flattened; static WebP conversion remains available. Source ICC, EXIF and unknown metadata retention are separate limitations.
- AVIF sequence export selects timed AV1 tracks by ID/time base/media duration, validates the auxiliary alpha type/link and aligned geometry/timing, and reads repetition from elst/tkhd. Supported 1–65536-frame sequences use RGBA8 edits, lossless RGB AV1 and a separate monochrome alpha track when needed. Validate exact rational frame times/durations, loop policy, track count and dimensions before publication. An absent repetition declaration remains absent. Shared staging/cancellation/source-identity guards apply; animated cross-format conversion fails rather than flattening.
- One-frame AVIF sequences use FFmpeg's single-sample MP4 output, then specialize its bounded tail moov to [AVIF sequence](https://aomediacodec.github.io/av1-avif/v1.2.0.html#av1-image-sequence) brands, picture/auxiliary handlers and alpha references. Preserve AV1 data/chunk offsets; restore exact unsigned sample ticks and 64-bit duration/repetition headers after temporary packet timing avoids MP4 rescaling limits. Do not duplicate a frame or flatten the sequence. These outputs are track-based, without a separate still cover item. AVIF decoding/scanning disables MOV's legacy negative-DTS heuristic for unsigned stts durations; display still applies its existing 10 ms minimum, while export retains raw timing.
- Static image export to AVIF and static AVIF conversion use the display decoder/shared raster edits, stage one RGBA8 PNG, then encode. Static AVIF uses lossless RGB AV1 plus monochrome alpha when any edited pixel is non-opaque; decode the result and require one frame, matching dimensions and exact RGBA before publication. The same encoder setup serves sequences. Conversions from AVIF to other static formats retain those formats' existing compression/alpha limitations, not a universal lossless guarantee. Source-stamp and staging guards cover both AVIF input and output.
- AVIF display applies container clean-aperture cropping, then validated quarter-turn/reflection matrices to merged RGBA before previews or edits. Validate FFmpeg's little-endian crop insets against the decoded canvas; compact RGBA rows in place. Explicit alpha transforms must agree with color, while omitted alpha transforms follow color for older encoders. Sequence export uses the same merged-RGBA transform order, retaining codec cropping but disabling automatic container cropping/rotation and clearing inherited display matrices to prevent double application. Saved pixels have transforms baked in before user edits; raw clap/irot/imir metadata is not copied. Both speculative and persisted AVIF thumbnails use the shared first-frame decoder and a format-specific cache revision, without invalidating other formats.
- Premultiplied AVIF color/alpha references are validated before decoding/export. Restore straight RGBA8 before transforms using nearest-integer component × 255 / alpha, clamp to 255 and clear RGB at zero alpha. Sequence export expresses this in planar-RGB geq to match display: alphamerge labels output straight, while FFmpeg's unpremultiply negotiates premultiplied input and can insert an unwanted extra multiplication. Preserve alpha and emit straight color; do not retain the source prem reference on restored output.
- Regular AVIF grids select the primary/alpha item as an FFmpeg tile stream group, not a standalone stream. A safe runtime adapter copies group-relative stream identities, uniform row-major geometry and group orientation into owned values. Bound both coded and displayed canvases, reject gaps/overlaps and tile transforms, and decode/copy one tile at a time with cancellation between tiles/rows. Clip edge padding to the displayed canvas before the existing merged-plane aperture/orientation/edit path. The pinned demuxer omits grid clap, so read only that item's iprp/ipma-associated property, reject duplicates, and resolve rational extents/signed center offsets with exact integer arithmetic. Fractional pixel boundaries fail explicitly; unrelated properties do not crop or invalidate this item. No parallel set of tile decoders or new codec dependency. Nested derived images/overlays are not implemented.
- When a grid has no whole-image alpha link, resolve all tile auxiliary/premultiplication links in one bounded metadata pass. Require complete, unambiguous alpha coverage, equal tile geometry and no tile transforms. Decode and merge each color/alpha pair before copying its rows; restore premultiplied tiles independently before primary-grid cropping/orientation. Reuse the ordinary merged-RGBA validation/restoration path without allocating another full alpha canvas. Whole-image alpha takes precedence over tile links.
- AVIF software color conversion uses each decoded frame's YUV range and matrix, refreshed even with a reused scaler. AVIF-specific thumbnail revision v4 invalidates prior color conversions and omitted tile-alpha previews without invalidating other formats. This is RGBA8 conversion, not full HDR/ICC color management.
- AVIF complex export edit lists currently fail explicitly. AVIF metadata editing/full native color fidelity are unsupported. Static export retains edited RGBA, PNG staging and a verification decode; source/output geometry checks bound individual canvases, not the whole process. The FFmpeg AVIF muxer buffers encoded media in memory. Long-animation/grid cost, fractional-pixel aperture semantics and HDR/ICC coverage remain unverified.

## Shell ordering and asynchronous services

Use live Explorer view order first, preferring a foreground matching window; otherwise resolve persisted Shell view/default template through IExplorerBrowser with EBO_NOPERSISTVIEWSTATE. Read public IFolderView2 sort metadata and enumeration; never parse registry Bags or substitute name sorting silently.

Initialize the Shell worker's STA only for a current folder request; retain it across requests and balance it on the owning thread, including unwind. Close/invalidation checks stop stale work between native phases, while waiting for a hidden view, and between enumerated items. Cancellation does not trigger filename-order fallback. The request loop remains message-aware when idle; provider drop signals closure without joining a possibly blocked Shell extension on the UI thread. These checks do not interrupt an in-flight native call or prove process-wide shutdown safety.

A shared immutable FolderSnapshot feeds filmstrip, playlist, and navigation. Filter supported media after Shell enumeration. Only on Shell failure use Windows natural-name fallback and label it. Empty-folder Open must not replace current media/history/navigation.

Shell work stays on a dedicated STA with message-aware waiting (MsgWaitForMultipleObjectsEx), not a condition variable that starves COM windows. Use generation/path checks, latest-request mailboxes, and debounced directory notifications. Refresh order on media load and filmstrip opening; reconcile by item identity/path, not old index.

## UI conventions

Keep a media-first grayscale UI: Figtree, proportional Japanese fallback, tabular numeric glyphs, Codicon, #2C2C2C hover backgrounds, centered shadow offset, and stable left-aligned status values. Tabs reserve 3 logical px top/bottom and the native 1 physical px boundary.

Media notices go in the left status area; image information stays right. Fullscreen uses the bottom bar. Save progress occupies the toolbar boundary, not ordinary image-navigation loading. Volume uses a 1.2s thin HUD without replacing the path notice.

Image scrollbar tracks and hit regions are inset without shrinking the displayed image viewport or its pan range. Fullscreen controls yield while the pointer is over the image-bar strip, so they do not cover its drag targets.

Filmstrip primary clicks dismiss it, including the current item; navigating elsewhere retains the unsaved guard. Middle-click registers an unloaded background tab while keeping filmstrip, its scroll/focus, and the current media/edits intact. Its inset scrollbar leaves non-draggable gutters that still accept panel wheel input.

Media previews are immediate, noninteractive and clipped to valid hover ownership; help tooltips keep their delay and close on clipped/covered/changed targets. The logo's directional menus and normal click/keyboard entry share context/dispatch. Exact widget values live with UI code and regression tests.

## Distribution boundary

The application is MIT OR Apache-2.0; dependencies retain their licenses. The desired eventual distribution is an assisted per-user Setup.exe with selectable destination, not a standalone exe or Electron migration. Publication remains separately scoped.

Native/source/license and install/update/recovery contracts are maintained in the [packaging references](DEVELOPMENT.md#packaging-references--only-when-needed), not duplicated here. Never infer LGPL suitability from FFmpeg's label alone, silently replace user DLLs, execute an old uninstaller during update, or recursively delete an install tree. Preserve explicit ownership, inventories, journals, rollback, and user media/settings.
