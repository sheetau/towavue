# Architecture

Current accepted contracts, organized by subsystem. For unfinished requirements and measured evidence see [STATUS](STATUS.md); for setup see [DEVELOPMENT](DEVELOPMENT.md). Versions live in Cargo.toml/Cargo.lock and rust-toolchain.toml. Edit the relevant section when a contract changes; do not prepend checkpoint reports.

## Platform and ownership

Windows 11 x64, Rust/MSVC. Windows 10 compatibility fallbacks may remain, but support and launch validation exclude Windows 10. winit owns events; egui renders through the patched egui-directx11 adapter, not eframe/wgpu. FFmpeg supplies media codecs, image/png supply image decoding, and D3D11/DXGI supply presentation.

| Boundary | Owns | Must not expose |
|---|---|---|
| towavue-core | Time, commands, history, geometry, tab and folder contracts | Unsafe code, Windows/FFmpeg types |
| towavue-runtime-windows | Native windows, COM/FFI, FFmpeg, D3D11, WASAPI, Shell, workers/queues/clocks | Native frame/COM/FFmpeg pointers to app or core |
| towavue-app | Event loop, UI state, tab orchestration, command dispatch | Ownership of native decode/render handles |

Unsafe operations stay behind safe runtime interfaces with explicit lifetime, thread, and synchronization invariants. Runtime frame leases own native surfaces; app receives safe metadata/events or RGBA images.

Keep the single-D3D11-device design: hardware decode, video processing, image/UI rendering, and all host windows use the same adapter/device. D3D11VA falls back to software, not CUDA/QSV. Default audio is event-driven WASAPI Shared, not Exclusive.

The four fixed blit/UI shaders are compiled from tracked HLSL into Cargo build output and embedded, retaining their original entry points, profiles and optimization flags. Device-owned shader resources are still created for each renderer; no native object is cached globally. Video-edit raster compilation remains separate. Do not commit generated shader bytecode.

## Playback, timing, and recovery

- The first fresh video frame after a seek or visibility refresh survives late-frame dropping even when the audio clock has advanced during preroll. Clear that protection when the frame advances into the current presentation; ordinary late-frame dropping then resumes. Keep generation/target validation and terminal-preview selection in the existing decoder paths.
- Video-resume storage retains the newest 200 path/length/mtime-stamped source positions in a bounded versioned file. Use original-source time, not edited-output time; zero is a reset record, not deletion, so older delayed writers cannot resurrect a position. Capture observation time with the playback snapshot. Serialize merges across windows with a lock and atomic replacement; reject changed source stamps and preserve malformed history except during an explicit clear. Its worker coalesces pending reads and bounded per-path writes, performs all filesystem work off the UI thread, and drains accepted writes on drop. Delivered reads still require app-side token/path validation. Length/mtime stamps are not content hashes, and synchronous shutdown draining can wait for filesystem IO.
- Clear Recently Opened also clears video-resume observations at or before the action's UTC cutoff. Version 2 persists that cutoff with the remaining records under the same lock/atomic replacement, rejecting older writes across workers/restarts while preserving later observations; v1 reads remain non-mutating. Coalesce pending clears monotonically and drain them on shutdown. Snapshot same-window active/retained owners before clearing so closing unchanged paused tabs does not recreate old positions. Invalidate pending resume lookups with a separate request revision and reload after the clear, without changing media generation, playback or edits. Recent and resume files are independent best-effort operations, not a two-file transaction; report each failure. Clear remains available when recent-path lists are empty. Clearing is not a disable-history preference; new playback observations can be saved.
- Fresh videos await the asynchronous resume lookup before opening playback; edited timelines also await duration before mapping the saved source point, using the existing next-surviving-join rule for deleted time. Validate media instance, path and loading state; failures open normally without a resume writer. Live retained/transferred tabs keep their owner and position, while interrupted pending opens request a fresh lookup on activation. Queue changed positions at most every five seconds and on navigation, close or shutdown, without changing edit history. Reset only after natural original-source completion, not a selected/trimmed endpoint or paused end-frame preview. Unchanged idle owners do not overwrite another window's newer observation. Writes are best-effort with status errors; abrupt process termination can lose the last interval.
- Before a speed hold activates, horizontal dragging on the audio/video Play button pins the cursor using the reading-mode mechanism. A net displacement of at least 24 logical pixels selects previous/next; the button glyph and status show that selection. Release dispatches one shared media-navigation command with the existing Shell order and unsaved guard. Returning to the center or interruption cancels without a Play click, rate edit or pause change. Drop the cursor lock before navigation/dialogs; already released queued gestures must not acquire a lock. Active holds retain their separate speed gesture, and active gesture notices do not expire while held.
- A stationary primary hold temporarily plays audio/video at 2x without editing history. Video can latch a rate by releasing at least 60 logical pixels below the original press after activation: set 2x, or reset to 1x when the original rate was already 2x. Show clamped percentage progress; returning above the threshold cancels the latch. Commit through the shared rate edit/Undo/export path and preserve the original paused/playing state. Consume the queued native release before cancelling the hold; interrupted gestures restore the original rate and never become a short Play click. Audio retains temporary-only behavior. A successful temporary-hold release clears its progress notice without an extra restoration message; restoration failures remain visible.
- Video and audio use independent demux/decode feeds and bounded queues. Audio output waits must not block video initialization or paused Seek. Do not drop packets or normal audio samples to relieve backpressure.
- Use the selected FFmpeg best streams consistently for playback, preview, waveform, and export. AVIF image display/preview and sequence export explicitly select timed color/auxiliary-alpha tracks: primary still items may have the same IDs and are not animation sources. Static AVIF display selects the primary item and its associated alpha property/reference.
- Media time is integer nanoseconds relative to the input origin. Audio clock is master while audio runs; monotonic anchors handle priming, video-only playback, and drained audio. Drop only eligible late decoded video frames at presentation; retain terminal video during a longer audio tail.
- Queued video frames retain their original-source PTS before timeline retiming. Advance that value together with the current pixels; pending replacements and held seek previews do not change it. Do not reconstruct it from the playback clock or inverse rounded edit mapping. A source PTS is not a unique frame identifier when the source contains duplicate timestamps.
- Seek invalidates generation, clears queues, seeks/flushes, decodes preroll, and primes at the target. Same-device seeks, rate changes and timeline re-primes hold the displayed frame without a pixel/surface copy until its replacement is advanced; this placeholder is not a fresh seek result, presentation metric or paused recovery anchor. Empty timelines clear it, and device recovery releases old-device frames. Check the selected key packet's PTS and back up a GOP if necessary; TS retains its packet/byte-position path. Do not replace exact frame selection with approximate keyframe display.
- Playback audio returns its safe queued handle before WASAPI initialization finishes on the existing owning thread. Keep the seek anchor/audio-master presence, ordered pause controls and bounded PCM channel during startup; no native objects move to the UI. Initialization failures wake the generation-bound owner through `Failed`, including initial endpoint invalidation; only an already initialized endpoint requests recovery. The separate synchronous audio constructors retain their startup error contract. Drop still requests shutdown and joins even during startup. Pipeline replacement cancels both producers and releases the video receiver before waiting for WASAPI shutdown, retaining the existing joined input/frame ownership.
- Explicit paused construction sends the initial audio pause before starting either decoder producer. A preview seek can therefore create a session without briefly starting audio; ordinary playback construction retains its playing behavior.
- Parallel software video keeps pre-target decoded frames native until selection, avoiding RGBA conversion/copy for discarded preroll. Retain the existing bounded channel and one last-preroll slot, frame counts and per-output cancellation checks; no native reference escapes the runtime. If EOF or a degenerate interval needs the last pre-target frame, materialize just that frame with the same scaling definitions/orientation before publication. Decoder references are still fully decoded, input-format changes remain errors, and normal selected frames/hardware decoding keep their existing paths.
- Audio-only workers reconstruct coarse-timestamp scalar-PCM/FLAC/Vorbis/Opus seek anchors by counting prefix packet samples without decoding them. PCM uses packet sizes; FLAC/Vorbis/Opus use FFmpeg's complete-frame header parsers. FLAC decodes from the target packet; Vorbis/Opus retain 250 ms of warm-up. Vorbis accounts for its discarded first packet; Opus decodes initial padding/first output before counting, retaining that decoder's priming state. Reuse sequential timestamp/gap rules; do not infer constant packet sizes. Side data falls back to decoding the remaining prefix except for Vorbis's exact full first-packet priming skip; unavailable parsing or invalid headers also fall back. This still reads the prefix and does not validate skipped compressed payloads. Sample-precision streams retain direct/preroll seeking. Decoder/resampler/parser creation stays on the audio worker. Set the decoder's packet time base before opening so priming removal also adjusts frame timestamps.
- Coarse-timestamp AAC-LC counts declared 960/1024-sample access units only after decoding initial padding and the first output to establish the sample axis. The live decoder must retain the declared profile/frame length, packets must begin with an ordinary audio element, and their durations must agree within container rounding. Other elements, missing/mismatched durations or subsequent side data use decoding for the remaining prefix. Resume decoding 250 ms before the target. Other AAC profiles keep the existing seek path; do not force full-prefix decoding merely to reproduce PNS random state.
- Coarse PCM/FLAC audio-only runs retain at most 512 scalar packet checkpoints in their open demux owner, learned approximately once per second during prefix counting or ordinary one-packet/one-chunk decoding after a sequential/exact start. Do not learn an approximate video-GOP/direct-start audio axis; subsequent side data or delayed/multi-chunk output stops learning for the run. Publish only positions distinct from their preceding/following audio packets; retain no payload or native decoder state. On reuse, explicitly seek the audio stream before a checkpoint, verify position/PTS/size/payload CRC and absent side data, then restore its preceding sample-axis value into the fresh audio pipeline. Cancellation remains checked during the bounded probe; a failed/missing match rewinds through the original prefix path. Source length/mtime mismatch disables checkpoints until a fresh input is opened. Other codecs keep their priming paths; an uncached seek still traverses the prefix, but a first seek can reuse already played positions.
- AAC/MP3/Opus/Vorbis audio feeds request 250 ms of decoder warm-up before clipping at the requested time; rewinding reused inputs includes negative-time priming packets. Video retains its separate GOP selection. Ogg/Vorbis and Ogg/Opus seeks back up a cached page boundary to avoid restoring an EOS page from an interior packet timestamp. These paths may decode additional container packets/pages; bit-exact compressed-audio seeks are not guaranteed beyond the tested prefix-counted paths.
- Frame stepping selects distinct actual PTS, not nominal FPS arithmetic. Forward steps may reuse the next sequential playback-queue timestamp only when the displayed frame equals the logical cursor, refresh is complete and the queued PTS is strictly greater. Deliver that result through the same serial/tab/media/generation guards; do not advance pixels or transport from the shortcut handler. Otherwise use the cancellable software timestamp probe. Its private H.264/HEVC decoder uses at most two native frame workers and omits loop filtering; it skips no frames and returns no pixels to display/export. Other codecs retain their prior decoder settings. The existing probe worker may retain at most 32 distinct scalar edited PTS from one completed monotonic scan, keyed by exact timeline and the frame-export file identity. Only exact observed anchors with an observed neighbor can hit; unknown edges, changed/busy/unverifiable sources and changed edits take the ordinary scan. Never merge separate scans or edit spans, retain native handles/pixels, or publish a cancelled/failed scan. Short identity leases end before scanning and are rechecked afterward; UI cancellation never locks the worker cache. App queues at most 32 discrete directions. Standalone video frame-key repeats submit only when the probe, discrete queue and current-picture refresh are idle; release leaves at most the accepted in-flight step, not a repeat backlog. First-step pausing, custom bindings and text/IME/modal ownership remain shared; audio's 10ms step does not gain repeat semantics.
- Results are scoped to owner and generation. Cancellation is cooperative at I/O/decode/conversion boundaries, not a promise to interrupt arbitrary FFmpeg or OS calls immediately.
- Wheel/volume shortcuts and mute control a tab-local 0–200% listening level, not edits or export. New audio/video tabs snapshot the last listening adjustment shared by the current WindowHost, initially 50%, including mute and its nonzero restore level. Capture background tabs when created, not when activated; transfers and old-tab activation never overwrite that shared seed. Do not persist it by file or across process restarts. Preserve the level and last nonzero unmute level across same-tab navigation, activation and live window transfer; discard them when the tab closes. Apply listening volume to the output without re-decoding, dirtying history or changing Undo/Redo, saved gain, waveform geometry or an active export request. Timeline gain edits remain the UI for saved volume changes, also up to 200%. The linear drag scale places 100% at the waveform center and reaches 200%/0% after moving 75% of the upper/lower half, respectively (one eighth of the full height from either edge). This extends travel per gain unit by 1.5 times; painting, hit testing and drag deltas share this scale. Existing edit-layer gain is retained independently. Compose listening and saved gain multiplicatively, without clamping their product to a single control's limit; the output ramp accepts up to 4× for combined legacy/listening gain, after local timeline gain. Amplification can clip at the output or export format limit; no limiter or normalization is implied.
- Listening-volume wheel and keyboard steps default to 2%. The Edit menu offers checked 2% / 5% / 10% choices; direct commands also work through the palette/custom bindings, and the existing cycle command remains available; this window-local preference spans tabs but is not persisted across restarts or transferred with a tab. Choosing a step does not change the listening level. Fractional wheel input remains proportional; each ordered delta is bounded before the next, with sub-percentage float residue removed so repeated full steps reach exact mute/full scale.
- Rate applies to playback and export. Rate changes preserve pitch but may re-prime; they are not guaranteed gapless.
- Ordinary rate playback retains its two square-root atempo stages and supplies finite EOF context. Publish at most ceil(received input frames / exact f32 rate) cumulatively; hold excess until more input arrives and discard output beyond that bound only at EOF. Use actual received samples, not duration estimates, and leave 1x playback byte-preserving. Ordinary non-timeline export uses its separate filter chain and the export sample-count contract below.
- Device removal pauses affected sessions and rebuilds all host surfaces on one new device before restoration. Failed recovery retains edits and stopped positions; Retry must not command dead workers. Endpoint recovery preserves the same ownership discipline.
- Fatal playback errors pause the affected active or retained clock and best-effort pause its output without replacing the original error. Late first-frame or audio-drain events must not start a clock unless playback is Playing. Successful graphics restoration does not clear an existing playback failure or turn it into a resumable pause, including at a playback-range boundary.
- HDR/10-bit presentation must follow an explicit validated color path; do not treat unverified passthrough or ignored metadata as HDR support.

## Windows, tabs, and input

- Before native egui input, read Windows wheel line/character preferences through the runtime's read-only `SystemParametersInfoW` wrapper, only for frames containing line-wheel events. Preserve raw ordered events for volume/zoom; normalize ordinary vertical/horizontal/Shift scrolling separately, retaining egui line smoothing and its default three-line baseline. Zero disables new scroll input; page-sized or larger steps are bounded by the viewport. Custom image/reading/list scrolling uses its target bounds. Stock egui areas register clipped content/scrollbar bounds, axes and offsets from their last completed layout; choose the innermost eligible area on the pointer's layer, yielding to its parent at an edge. Discarded/absent layouts are not reused. Use window extents only without an eligible rendered area; keep egui's smoothing rather than introducing another scroll clock. Point/touch input is unchanged. Keep raw events scoped to one frame (including discarded passes), and do not modify OS settings or add an idle polling loop.
- Media ZoomIn and Grabbing use the owner-approved [Chromium cursor assets](../crates/towavue-app/assets/cursors/README.md), including their original license and hotspot provenance. Cache two native winit cursors per window, rebuilding only for a DPI change; nearest-neighbor scaling preserves the original raster. Override only these two media glyphs and restore ordinary cursor mapping afterward, respecting pointer presence and idle hiding. These media glyphs are independent of host-owned tab/filmstrip feedback and OS caption drawing.
- Enabled buttons, thumbnail cards and form choices use PointingHand on hover; disabled controls do not. Prefer the shared button style, with explicit feedback for custom hit regions and non-button form widgets. Preserve text input and specialized selection/resize/pan/host-drag cursors; native caption pointer handling remains OS-owned.
- Keep content panels/input fields black and floating windows, menus, tooltips and the palette on shared #0c0c0c; tabs retain their separate state colors. Single-line form and palette inputs center text, hints and carets vertically; multiline fields remain top-aligned. Placeholder text uses the shared border color without dimming ordinary muted labels or entered text. Text-edit carets use white across the shared style. Compact seek track/progress span the full width in idle and active states; only the handle center's travel is inset, with unchanged pointer/value mapping. A committed pointer position remains painted throughout its release frame, including discarded passes, then yields to the updated transport/folder position; do not replay the seek action.
- The host shares graphics across windows. Normal launches from the same SID/session/executable forward path-only requests with acknowledgment; failure must not silently create a duplicate host. No live-state transfer between independent old processes.
- Ignore native synthetic key presses before command, gesture and egui routing: focus changes report already-held keys, which must not replay Enter or other commands in a newly activated window. Keep synthetic releases to clear held-key/widget state. New media windows start in normal windowed mode independently of the source window's fullscreen state.
- Launch, tab-merge and filmstrip-drop activation use the runtime's UI-thread `activate_window` wrapper, never winit's `focus_window` (the pinned Windows implementation synthesizes Alt input). Only visible, non-minimized windows are eligible; use `SetForegroundWindow` without synthetic keys, input-queue attachment or forced retries. Refusal leaves the completed open/transfer intact and allows the user to activate the destination normally. Do not add a viewport-focus route that bypasses this policy.
- Image/video forward/backward folder navigation has a window-local Stop at ends / Loop at ends preference, initially Loop to preserve the existing behavior. Apply it to mixed-kind and same-kind navigation, including queued image steps; reaching an edge under Stop neither wraps, reloads the current source nor opens an unsaved guard. Reading mode always stops, and its folder-end choices are disabled without overwriting the stored normal-view preference. Preserve Shell order and existing unsaved/export guards. Numbered image jumps still clamp explicitly, and audio queue repeat/shuffle and video EOF repeat keep their separate contracts. The preference is not persisted or transferred with a tab.
- Choice submenus display the current volume step, audio-repeat mode and folder-end policy with mutually exclusive checks. Direct selections are idempotent commands with ordinary context/modal validation; audio selections change only the active tab's queue mode. Cycle aliases remain available to shortcuts/palette and transport buttons. Size child menus from their own rows and the available cascade side for both root-menu and directional-logo entry, keeping keyboard entry/back/selection and focus reveal inside the menu tree.
- Gallery is an ordered non-media tab, initially present for a pathless user launch and retained when files subsequently open. File/folder launches and hidden transfer destinations start without Gallery; an unsupported initial file or empty initial folder restores it once opening completes without media. Open Gallery (File menu, customizable Ctrl+T, logo middle click) activates the existing Gallery in that window or creates it with a fresh ID. Media-only accessors exclude Gallery; tab ordering, cycling, menus and drop gaps include it. The last Gallery keeps a disabled close button; closing the last media tab creates Gallery only if none remains. Activation retains media/edit/view state and background audio. Transfers use the same validation and destination-ready gates; an actually empty source closes without creating Gallery. A newly detached media window contains only its transferred tab. Gallery transfer into a window already containing Gallery reuses that destination tab.
- Reopen Closed Tab uses one 32-entry window-local stack for media paths and Gallery query/type-filter snapshots, in actual close order. A protected last Gallery and transfer removal add no history. Modal guards cannot consume an entry. Reopening Gallery uses the normal activation route to retain background media/edit state and reuses an existing Gallery instead of creating duplicates, restoring the closed query and filter. Media reopen still forces a fresh tab without resurrecting discarded edits.
- Gallery's fixed search/type-filter/open-action header sits outside the scrolling recent grid and shares its width and horizontal offset, leaving the same room for the rail; do not stretch the header to the window edges. Match all whitespace-separated search terms against the full path, case-insensitively with normalized separators; preserve recent ordering and apply both the query and selected media type before handling cards. The search field contains the type-filter button followed by Clear on its right; reserve their slots outside the editor's horizontal scroll and caret clip. Clear removes only the query, preserves the type/history and returns focus to the editor; keep its empty-query slot disabled. The type menu defaults to All; disable types absent from the full Gallery history, independently of search terms. Preserve a selected type through history refreshes, even while it has no matches. Reuse the accessible text input and existing bounded thumbnail worker. Query or type-menu changes reset body scrolling; modal confirmation and grid-overlay state disable search and open actions without dimming the grid or clearing its bounded thumbnail preparation set. Middle-click creates an unloaded background tab (including a new instance of an already-open file), retaining Gallery's query/view and existing media state; audio/video capture the shared listening-volume seed at creation. Revalidate the active Gallery, visible query/type/history membership and input guards before accepting that action. Empty history shows drop guidance, while zero search results shows a distinct message. Search and type selection survive media activation, reset on Gallery close, and move with Gallery (including when reusing the destination Gallery). Widget IDs are scoped to the Gallery identity, so reopening does not inherit an old editor's focus/undo state.
- Recent history uses one bounded worker, cross-process file lock and atomic replacement. Version 4 records explicit file/folder kinds, UTC last-opened milliseconds and removed derived-folder paths, with up to 10,000 files, 40 explicit folders and 10,000 derived-folder exclusions in a bounded 16 MiB UTF-8 file; v1/v2 load as files and v3 retains kinds without rewriting or inventing legacy dates. Newer timestamps win delayed batches. Clear replaces both groups at its serialized write, discards earlier opens queued on that worker and retains subsequent opens; it never deletes source media. Only successfully opened, explicitly requested folders are persisted as folder records. At delivery, derive file parents and merge them with explicit folders for both recent-folder consumers: newest timestamps first, stable unknown-date order, duplicate paths removed. Individual removal deletes only the matching history entry. Removing a folder also persists its exclusion from the derived-parent projection, atomically with the entries, while retaining child file history. Keep exclusions only for direct parents of retained file entries; a later serialized successful open of that folder or a direct child file restores it. Clear removes these exclusions too. Removal leaves source media, loaded/edited tabs and resume positions intact. Queued file mutations suppress older completed snapshots. This bounded projection adds no filesystem queries. Gallery receives file entries only and converts dates to local months on delivery. On initial history load and Gallery activation (including explicit Open Gallery reuse), the same worker checks file paths outside the history lock/UI thread. Hide only confirmed absent sources from Gallery cards, type availability and the month rail; retain entries on IO errors and restore cards on a later successful check or recorded open. This transient mask does not rewrite persisted history, alter Open Recent/Go to File, clear resume records or close loaded/edited tabs. Requests coalesce; pending opens, clear and shutdown interrupt the archive scan between individual filesystem calls. An interrupted scan retains the last completed mask and retries after queued updates; a single Windows filesystem call can still block. No filesystem watcher or per-frame presence checks are added. History parsing/deduplication is linear, and each pending batch is sorted/merged once rather than once per entry. Its rail contains populated months from filtered cards plus unknown dates; equal slots remain selectable when months share a row, while navigation uses measured row offsets. Gray dots/year labels and white position/gray hover-focus bars replace the ordinary scrollbar. With newer months above older ones, year labels end at the lower boundary of that year's oldest populated month; a single year ends at the rail bottom. Use measured text bounds and suppress colliding labels on short rails without changing month hit regions. Both bars use 85% of the rail width. Hover/drag month help is painted immediately to the active bar's left, vertically centered and without an input surface; month buttons retain accessible labels. Pointer clicks and captured drags, including release coordinates, share the marker's inset travel and piecewise month-offset mapping. Remember ambiguous equal-row/bottom positions only while offsets and layout remain unchanged; empty results clear them. Keyboard/accessibility still targets the chosen month's first row; native wheel pages use the actual body viewport.
- Gallery caches its available/filtered paths and first-card month indices; rebuild on history delivery/clear or query/type changes, not on each redraw. Scrolling cards reach the media bottom; the date rail spans the media height with its own existing top/bottom insets. Header icon buttons retain their glyph size in 20-point square controls centered on the 24-point search field; inline controls have two-point outer/gap insets. An active media-type filter uses the foreground color. Recompute month offsets from the current grid geometry so resizing still reflows correctly. Instantiate only viewport-adjacent rows and the focused row's immediate neighbors, with path-stable card IDs; preserve ordinary egui arrow/Tab/accessibility focus and manual scrolling. Offscreen row geometry is arithmetic, and visible previews still lead the existing 64-request/texture working set. Open Recent menu limits remain ten folders and ten files.
- File > Open Recent lists up to ten merged recent folders, then ten files, with separators and Clear Recently Opened. Measure labels and cap the submenu to free space beside its parent's outer frame, allowing the submenu frame, two-point gap and one physical pixel for rounding. A normal left-to-right cascade keeps growing to the right instead of flipping over its root menu. Direct entry can use the opposite free side near the viewport edge. Do not impose a fixed 520-point ceiling or stretch short lists across the window; path and Clear rows can truncate at the available side width. Normal file activation reuses an existing tab without reopening its source (including moved/deleted sources); otherwise it opens a tab. Ctrl requests a separate shared-device host window; Alt replaces the active media through the unsaved/export guards and opens a media tab when Gallery is active. Folder replacement resolves through Shell order and is bound to the originating tab/media generation; stale results cannot replace a later owner. Clear does not close tabs or clear the separate recently-closed-tab stack.
- The shared quick picker uses an editable leading `>` for commands and no prefix for Go to File; Open Recent Folder searches the merged explicit-folder/file-parent list. Typing `>` from that picker enters commands, and deleting it goes to files. Keep disabled commands discoverable on Gallery. Recent results precede deduplicated file results; preserve the selected path when results reorder and retain name/parent descriptions and full-path accessibility/help. Normal/Ctrl/Alt activation reuses the same recent-opening guards and host route. Defaults are Ctrl+P and Ctrl+F; preserve existing custom bindings/prefixes when adding defaults. Shortcut format v7 migrates only an older single Ctrl+Alt+O recent-folder default when Ctrl+F is free; explicit v7 bindings, custom alternatives and prefix conflicts retain their configured keys. Existing files are interpreted in memory, not rewritten on load. Modified picker commands may enter from focused text, but not during native IME composition or a modal guard. Reset the editor cursor and undo state when explicitly reopening; IME confirmation must not activate a result. Explicit picker entry reloads file and command histories on the existing worker, without a source-presence scan or periodic polling. File/folder rows show the smaller muted parent path adjacent to the name and inline first-row group labels at the right, before a separate accessible close button. Selected/hovered rows reserve that button's space by reducing content width. History removal keeps the picker open and chooses the adjacent row; dismissing a search-only result hides it for the current query, with no persisted search exclusion. Query change or reopening clears local dismissals; stale asynchronous results cannot restore a dismissed row within the query. Recent files precede a separated file-results group without changing fixed virtual-row height.
- Command-palette activation maintains up to 50 registered command IDs in most-recent-use order; ordinary menu/shortcut dispatch does not enter that history. Recent commands precede ordinary matches without duplication, remain context-sensitive, and retain selected command identity across asynchronous history delivery. Inline group labels and a separator distinguish recently used and other commands. The selected or hovered recent row exposes a separate accessible close button; removal leaves the command available in the ordinary group and keeps the picker open. The existing recent-history worker serializes command edits into a separate bounded UTF-8 file with its own cross-process lock and atomic replacement. Coalesce by command identity in last-action order, suppress stale command snapshots while newer edits are queued, and flush queued edits on shutdown. Reading unknown command IDs does not rewrite the file; malformed/oversized stores remain untouched and report an error independently of file history. Clearing Recently Opened does not clear command MRU. No additional worker or UI-thread persistence is introduced.
- Tabs own history, export target/options, image/view/reading state, transport, focus role, and scroll positions. A fresh media tab starts with filmstrip closed, including background creation; save the departing tab's overlay before resetting, and restore retained tabs' own overlay state on activation. Same-tab navigation retains its overlay. Pointer activation of a media tab clears its widget focus and saved media-control focus role so ordinary media shortcuts remain available. Media buttons, audio-list rows and shared seek/timeline value controls likewise release focus after pointer clicks, holds and drags; explicit keyboard/accessibility focus and non-pointer role restoration remain supported. Starting a pointer view/selection gesture also releases numeric-edge focus and forgets its saved role. Background audio continues. Hidden video limits decode work and retains a frame without pinning an entire decoder surface pool.
- Media and Gallery tab titles keep their complete single-line text and accessibility labels; clip at the close-button slot without ellipsis. Match the reference title mask: full visibility through 80% of the available text width, then fade to the actual idle/active/hover background at its right edge. The optional audio slot changes only the text origin and available width. The tab strip alone uses 20-point fades to fully opaque black on clipped edges, including one physical pixel of solid black at the boundary. Paint these after tab contents and before the floating scrollbar; preserve other scroll-area/menu fades and tab input ownership.
- Playing tabs with a live, undrained audio output show a speaker before the filename, or a mute icon when their listening level is zero. Paused, ended, failed and audio-less tabs omit it. Clicking the icon toggles that tab's listening mute without activating it or changing edits; its separate hit region does not initiate tab dragging. Pointer release returns keyboard input to the current media, clearing its saved control role but preserving background tabs' roles; explicit accessibility/keyboard focus remains supported. The tab context menu also exposes Mute tab/Unmute tab for paused or unopened audio/video without activation or playback. A decoded source without audio, image, Gallery or stale target has no eligible mute action. Unopened media stores its listening level until loading discovers its streams; source-matching live/retained sessions apply that level immediately, preserving edit gain and transport. The icon does not represent saved timeline gain or measured signal loudness; accessibility keeps the plain filename, describes audio state separately and names the mute/unmute button. Background state transitions request redraw without continuously repainting static foreground media.

- AVIF software color conversion uses each decoded frame's YUV range, matrix and declared chroma location. Static export retains edited RGBA, PNG staging and a verification decode; source/output geometry checks bound individual canvases, not the whole process. The FFmpeg AVIF muxer buffers encoded media in memory. Long-animation/grid cost, fractional-pixel aperture semantics and HDR/ICC coverage remain unverified.

## Shell ordering and asynchronous services

Each native window owns its taskbar integration, installed before the window is shown. Wait for `TaskbarButtonCreated`; recreate the thread-local Shell connection and invalidate cached state after another readiness notification. Do not initialize COM without progress or transport to show, or resend unchanged state on every wakeup. Native callbacks only enqueue owner-window events; no rendering or COM work occurs in the subclass. Remove the subclass and balance its callback ownership on native destruction or owner drop. Failures are nonfatal and are not retried every frame. A window-local message filter admits only the scalar readiness and `WM_COMMAND` protocols so Explorer can reach an elevated process; dispatch only known thumbnail button IDs and preserve preexisting filter permissions when the owner drops. No process-wide filter or OS setting is changed. [Windows taskbar APIs](https://learn.microsoft.com/en-us/windows/win32/shell/taskbar-extensions), [window-local filtering](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-changewindowmessagefilterex).

Thumbnail transport registers previous/play-pause/next once per Shell epoch, then updates the same three button IDs. Use the active audio/video tab; hide for images/Gallery, disable blocked operations, and revalidate tab/media identity, owner revision and current guards when queued clicks arrive. Dispatch shared commands, including unsaved navigation guards, without activating another tab/window. Icons reuse the bundled Codicon glyphs with built-in contrast at the current pixel density; an icon-only CPU font collection prepares them without a UI pass and is then released. Export progress is independent of transport: use the toolbar's edited-duration/normalization estimate, show indeterminate progress for unknown work or pending cancellation, and clear on every terminal outcome. Schedule both independently of drawing, including while minimized; export progress stays with its window rather than following the selected tab.

Go to File's recursive filename search is independent of Shell navigation ordering. One latest-task worker per window enumerates metadata only, retains the top 1,000 ranked paths, and reports total matches and exclusions. Depth-first traversal is bounded to 128 directory iterators; do not follow descendant reparse points. Unreadable entries and depth exclusions remain visible rather than implying complete coverage. Request revisions reject stale publication, including A-to-B-to-A changes; clear/close cancels without joining filesystem work on the UI thread. Query changes and source-root changes invalidate prior results; stable frames share the ready result without rescanning.

Use live Explorer view order first, preferring a foreground matching window; otherwise resolve persisted Shell view/default template through IExplorerBrowser with EBO_NOPERSISTVIEWSTATE. Read public IFolderView2 sort metadata and enumeration; never parse registry Bags or substitute name sorting silently. Hidden views must finish initial enumeration before capture: successful navigation or obtaining IFolderView2 alone is insufficient. Advise IExplorerBrowserEvents before navigation and subscribe to the hidden view's [DShellFolderViewEvents.EnumDone](https://learn.microsoft.com/en-us/windows/win32/shell/shellfolderviewoc-enumdone) in OnViewCreated, so even a synchronously completed empty view is covered. Pump the owning STA while waiting; an unfinished enumeration remains loading until ready or cancelled, rather than timing out into name order. The view event sink owns an atomic completion state; the browser sink owns a thread-bound subscription slot. Neither borrows stack storage. Unsubscribe view and browser events on the same STA, releasing RefCell borrows before native teardown calls, before browser destruction. Do not replace a user-owned live Explorer view's callback.

Initialize the Shell worker's STA only for a current folder request; retain it across requests and balance it on the owning thread, including unwind. Close/invalidation checks stop stale work between native phases, while waiting for a hidden view, and between enumerated items. Cancellation does not trigger filename-order fallback. The request loop remains message-aware when idle; provider drop signals closure without joining a possibly blocked Shell extension on the UI thread. These checks do not interrupt an in-flight native call or prove process-wide shutdown safety.

A shared immutable FolderSnapshot feeds filmstrip, playlist, and navigation. Filter supported media after Shell enumeration. Only on Shell failure use Windows natural-name fallback and label it. Empty-folder Open must not replace current media/history/navigation.

Shell work stays on a dedicated STA with message-aware waiting (MsgWaitForMultipleObjectsEx), not a condition variable that starves COM windows. Use generation/path checks, latest-request mailboxes, and debounced directory notifications. Refresh order on media load and filmstrip opening; reconcile by item identity/path, not old index. Within-tab loading of a known item in the same folder reuses an outstanding refresh and retargets its completion to the new current path, without restarting enumeration. Unlisted items, different folders and pending folder Open requests retain invalidation; explicit/filmstrip/watcher refreshes still request fresh order.

## UI conventions

Timeline In/Out/Length captions and the status position/duration while a timeline is visible use `hh:mm:ss:mmm` (hours may exceed two digits); numeric accessibility/edit values remain seconds. Compact playback without a timeline retains the shorter clock. Ordinary successful seeks do not emit a redundant position notice; empty/outside-trim diagnostics remain. Timeline captions share 11-point text: Volume/In align 24 logical pixels from the left, Length/Out from the right; held selection/stretch length stays centered. Loading/refinement is centered inside the track without covering those captions. Hover help belongs to the playhead, gain line, selection edges or selected area, not empty timeline space. Explicitly described truncated labels disable the built-in elision tooltip to avoid duplicate help.

Keep a media-first grayscale UI: Figtree, proportional Japanese fallback, tabular numeric glyphs, Codicon, #2C2C2C hover backgrounds, centered shadow offset, and stable left-aligned status values. Play/pause use solid vector counterparts to the Codicon outlines, retaining shared button interaction and focus roles. Tabs reserve 3 logical px top/bottom and the native 1 physical px boundary.

The owner-supplied multi-size ICO is embedded as executable icon group 1. Load small-window and taskbar icons through winit's Windows resource API at creation and DPI changes; no runtime asset file or media-decoder work is required. winit owns their native lifetimes. This does not change OS-drawn caption controls or the custom in-app logo.

Media notices go in the left status area; image information stays right. Fullscreen uses the bottom bar. Save progress has priority on the toolbar boundary. Background folder-order status text has a separate 200 ms quiet interval starting at each refresh request; completion cancels it, replacement requests restart it, and drawing schedules the remaining deadline even without a fullscreen toolbar. Explicit folder opens and diagnostics remain immediate. Foreground image/media and folder loading use the same one-physical-pixel white segment after 200 ms; unknown work has no percentage. Keep animation continuous across the same media's loading stages, reset the delay for a different tab/media instance/folder request, and remove it on completion or failure. Waveform loading/refinement uses a clipped text label inside the visible timeline, never the toolbar boundary or path notice; hide it on completion or when that timeline is hidden. Timeline hover and selection dragging use the native text caret; gain, edge and seek gestures retain their directional cursors. Background thumbnails/prefetch do not drive the border. Schedule animation only while visible activity remains; cached/brief navigation must not flash. Accessibility distinguishes media loading from export progress. Volume uses a 1.2s thin HUD without replacing the path notice.

Fullscreen status opens only on bottom-edge hover for image, video and audio, never for notices, selections, Tab traversal or saved focus. A pointer gesture begun on the visible bar retains it through release, including batched events; content gestures cannot reveal it. Hidden controls relinquish their focus without affecting normal-window controls or selection-edge focus. Audio and video use the compact seek bar above the visible hover status; no hidden audio editing footer reserves content space. Existing modal, popup and image-gesture exclusions remain.

Five-second keyboard seeks report signed net movement in white after the muted current time, separated by a space without parentheses, for example `09:29 +15s / 36:17`, without replacing the path. Sum accepted, clamped seek deltas, not elapsed playback time. Each successful relative seek refreshes an independent four-second deadline, including an idle wakeup while paused. Reset after expiry, another notice, an absolute seek or a media/tab change; do not retain or transfer this transient display with a tab. Compact clocks retain truncation and their full-time tooltip. Preserve errors, empty-timeline and out-of-trim diagnostics. These notifications do not edit media or alter seek/Undo semantics.
